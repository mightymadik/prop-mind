# Правила разметки relevant_source_ids

Разметка — эталон для Recall@10 и MRR слоя поиска. Скрипт: `scripts/label_relevant.py`.

## Кто размечает

| `semantic` кейса | Разметка | `relevance` |
| --- | --- | --- |
| `empty` | автоматически: все объекты, проходящие `expected_filters` | `auto` |
| `required` | вручную, из пула кандидатов | `manual` |
| уточнение (`needs_clarification`) | не размечается | — |

- **Автоматическая разметка** пересчитывается при каждом запуске скрипта, поэтому после
  изменения данных (новые объекты, `seed_listings.py`) запусти его ещё раз.
- **Почему так.** Без смысловых требований подходящим считается любой объект под фильтрами,
  а таких бывает больше, чем помещается в пул из 30: ручная разметка из пула была бы
  неполной и занижала бы Recall.
- **Что это значит для метрик.** На эталонных фильтрах поиск возвращает только объекты под
  фильтрами, поэтому у `auto`-кейсов Recall@10 близок к 100% и почти ничего не говорит о
  ранжировании. Информативны они в сквозном прогоне через парсер. Качество ранжирования
  меряют `manual`-кейсы.
- **Чем пожертвовали.** У `auto`-кейсов не отсеиваются объекты, где описание противоречит
  полям (в полях «с ремонтом», в тексте «нужен ремонт»).

## Ручная разметка: что считать подходящим

- **Объект подходит, если его стоило бы показать человеку с этим запросом** — в топе
  выдачи, без оговорок.
- **Все явные условия запроса выполнены.** Кандидаты уже отобраны по `expected_filters`,
  но поля объявления могут расходиться с текстом: если в полях «с ремонтом», а в
  описании «нужен ремонт» — не подходит.
- **Смысловая часть запроса подтверждена описанием.** «Тихий двор», «вид на горы» и т. п.
  должны быть в описании прямо или однозначно. Не упомянуто — не подходит, даже если
  объект хорош по полям.
- **Сомневаешься — не подходит.** Эталон должен быть строгим, иначе метрика размывается.

## Как размечать вручную

- Смотри на поля и на начало описания; полное описание кандидата — команда `? N`.
- Метод, которым найден кандидат, и `source_id` не показываются (вместо него короткий
  хеш), порядок перемешан: не ищи закономерность в позиции.
- Подходящих нет — пустая строка, это тоже валидная разметка (`[]`).
- Пул — до 30 кандидатов; подходящие за его пределами не размечены, поэтому Recall
  смысловых кейсов — оценка сверху. Это обычное ограничение разметки по пулу.
- Решения по спорным кейсам записывай сюда, в раздел ниже, чтобы потом размечать так же.

## Разметка ЖК (новостройки, 6.3)

- **Единица разметки — ЖК**, а не квартира: смысловые пожелания («тихо», «для семьи с детьми»,
  «рядом бизнес-центры») описывают комплекс. Квартиры под жёсткие фильтры уже проверены кодом.
- **Разметка полная:** оцениваются все ЖК, у которых есть свободная квартира под `expected_filters`
  (их десятки, не сотни), а не только топ вариантов поиска. Неразмеченных в выдаче нет.
- **ЖК подходит, если описание прямо или однозначно подтверждает каждое смысловое пожелание
  запроса.** Поля ЖК (инфраструктура, класс, район) учитываются, но смысл должен подтвердить текст.
  Близкое по смыслу засчитывается («двор без машин, дети гуляют» — для «детские площадки во дворе»
  да, если площадки или игры детей во дворе названы); общее не подтверждает частное.
- **Сомневаешься — не подходит.**
- **Уточнения после ручной проверки (6.3):**
  - синонимы засчитываются: «озеленённый двор» = зелень во дворе, «парк рядом» = есть где гулять,
    «торговые галереи» = ТЦ;
  - если в запросе несколько пожеланий одного смысла (зелень / чистый воздух / подальше от центра) —
    достаточно двух из трёх;
  - в списках вида «кафе, театры, магазины» главное — повседневная городская среда: отсутствие редкого
    пункта (театры) не делает ЖК неподходящим.
